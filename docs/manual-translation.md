# 论文精读翻译

## 这条路线解决什么

paper-lens 应用内有两个自动解析引擎：本地几何规则、整页视觉模型。两者都在**猜**版面，
上限有限。而我读 PDF 时是**整页看**的——和人一样，不需要判断"这块是正文还是插图"，
直接在理解内容。所以碰到下面这些情况，直接由我来读、来译，效果远好于任何自动流程：

- 公式密集的论文（自动流程会把公式截成图，或还原成 `∂w⋆/∂rˆ` 这种乱码）
- **PDF 文本层本身损坏**：`∂` 存成 `@`、`≠` 存成 `6=`、希腊字母直接丢失
- 双栏、多栏、图文混排
- 读者要的是"读得懂"，不是"跑得快"

代价是慢，而且占我的上下文。一篇 40 页的论文大约要分 4–6 轮读完。

## 工作目录

每篇文章一个目录，放在 `~/Desktop/工具/PDF双语翻译/精读稿/<短名>/`：

```
source.pdf     原文（复制一份进来，别依赖 Downloads 里的原件）
script.txt     我写的稿子，可分批追加
doc.json       编译产物，导入用
```

**不要把稿子放在 `/tmp`**，那里会被清掉。

## 工作流

### 1. 勘察

```bash
python3 ~/Desktop/工具/paper-lens/tools/survey.py <pdf>
```

输出每页的文本块数、矢量绘图数、位图数。矢量绘图数是最有用的信号：正文页通常是 0
（偶尔几条分隔线），一张折线图则是几百条独立线段。据此判断哪几页需要 `@fig`。

### 2. 读原文

用 Read 工具带 `pages` 参数读 PDF，**每次不超过 8 页**（再多会稀释注意力，公式容易抄错）。
**读完一批立刻写这一批的稿子并追加落盘**，不要攒着——中途被打断就全丢了。

### 3. 写稿

格式见下。写的时候守三条：

1. **公式照抄成 LaTeX，不要意译。** 行内 `\( ... \)`，行间用 `@math` 块，编号用 `\tag{1}`。
   抄完回头对一眼原图，**下标和撇号最容易错**。
2. **译文只用逗号句号**，不用设问、不用空转折、不用修辞收尾；承接靠事实 callback，
   不靠连接词。用词干练。
3. **一个块对应原文一个自然段。** 不要合并，不要拆开——块是标注和翻译缓存的单位。

### 4. 编译

```bash
python3 ~/Desktop/工具/paper-lens/tools/build.py <pdf> <script.txt> <doc.json>
```

工具按 `@fig` 给的坐标从 PDF 裁图（200dpi，WebP），内嵌成 dataURL，打包成一个 json。
每次追加完稿子都可以重跑，覆盖输出。

### 5. 交付

把 `doc.json` 复制到用户能拿到的地方（例如 `~/Downloads/<中文名>-双语精读.json`），
并告诉他：

1. `git pull`（导入按钮是新功能）
2. **`Cmd + Shift + R` 强制刷新**（`python3 -m http.server` 不发缓存头）
3. 首页拖拽框**下方**点「导入已翻译文档（.json）」

## 稿子格式

```
@meta
title-en: Selection of Estimation Window in the Presence of Breaks
title-zh: 存在结构断点时估计窗口的选择
file: estimation-window.pdf

@page 2                         之后的块都算第 2 页（影响页码角标和裁图）

@h1 / @h2 / @h3                 标题，字号最大的那个 h1 会成为全文标题
@p                              正文段落
@note                           脚注、作者信息、关键词这类小字
@cap                            图题表题
@math                           行间公式，只写 LaTeX，不译
@ref                            参考文献条目，不译
@fig x0,y0,x1,y1                按 PDF 坐标（pt，左上为原点）从当前页裁图
```

块内用单独一行 `--` 分隔原文与译文。没有 `--` 的块只有原文（`@math` `@ref` 用这种）。
空行结束一个块。

例：

```
@p
Here \(\mathbf{1}_{\{t \leq T_1\}}\) is an indicator variable that takes the value of one.
--
其中 \(\mathbf{1}_{\{t \leq T_1\}}\) 是示性变量，取值为 1。

@math
\[ y_{t+1} = \boldsymbol{\beta}_1'\mathbf{x}_t + u_{t+1} \tag{1} \]
```

## 怎么定 `@fig` 的坐标

先看 `survey.py` 指出哪页有图，再读那一页的图像，按版面估坐标（页面通常 612×792pt，
左上角为原点）。**拿不准就框大一点**——多留白不影响阅读，切掉半张图很难看。
编译后回看 `build.py` 输出的尺寸是否合理。

矢量图别指望程序自动聚类：一张三面板折线图在 PDF 里是几百条独立线段，坐标轴之间
横向能隔几十个点，按矩形邻近度聚类必然碎成一堆。自己看图给坐标最省事。

## 注意

- **公式对不对，只能靠回看原图核对。** 这是整条流程里唯一没有自动校验的环节。
- 参考文献用 `@ref`，不要翻译。整页文献条目翻出来既费事又没人看。
- 页眉页脚、孤立页码不要写进稿子。
- 稿子分批追加到同一个文件，最后一次性编译。
- 交付前确认页码覆盖完整：`grep '^@page' script.txt`。

## 已知问题（未解决）

### 点公式问 AI，在精读稿里拿不到公式内容

阅读器里点一个公式会打开 AI 侧栏（`reader.js` 的 `onFormula` → `main.js` 的
`askFormula`）。这条链路是为**自动解析**设计的：那时公式是一张截图，`askFormula`
把 `block.blob` 当图片发给读图模型。

而精读稿里的公式是 `kind: 'math'` 的 **LaTeX 文本块，没有 blob**。结果是：

- `imageBlob` 为空 → 读图模型收不到任何图
- `ocrText` 取的是 `block.ocr`，而 math 块的内容在 `block.text` 里 → 也没传过去

于是点了公式，AI 只能靠 `contextAround` 给的上下文瞎猜，**看不到公式本身**。

要修的话：`askFormula` 对 `kind === 'math'` 的块，把 `block.text`（LaTeX 源码）
当 `ocrText` 传进 `Conversation`；侧栏标题也该显示渲染后的公式而不是"公式/表格"。
`ai.js` 的 `_firstUserContent` 已经支持 `ocrText` 且在无图时会降级，接上即可。
